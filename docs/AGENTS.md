### Field Semantics

| Field | Type | Values | Meaning |
|-------|------|--------|---------|
| `verdict` | string | `DEAD` `ALIVE` `MODIFIED` `STRENGTHENED` `SUSPENDED` | Outcome of anti-example attacks. DEAD = counter-example found. ALIVE = no counter-example found after maximum effort. |
| `survival_pressure` | float | 0.0–1.0 | How hard the axiom was attacked. 1.0 = CRITICAL attacks survived; 0.95 = DEAD under severe pressure |
| `attack_type` | string | `reverse` `cross_domain` `counterfactual` `internal_contradiction` `none` | Methodology used to challenge the axiom. `reverse`=opposite claim also holds. `cross_domain`=transferred to new domain. `counterfactual`=removing axiom doesn't break system. |
| `epistemology_lesson` | string | free text | What this outcome implies about knowledge formation. Empty string if not generated. |
| `axiom_name` | string | 生长\|光影\|色彩\|布局\|叙事\|边界\|自由\|因果 | Which axiom was tested |
| `axiom_id` | string | `{name}_v{1,2,3}` | Versioned identifier. v1=原始版, v2=改进版, v3=最新 |

## Interpretation Rules for AI Agents

### When to trust an axiom constraint

- `verdict=ALIVE` + `survival_pressure>0.9` → Strong constraint. The axiom survived CRITICAL attacks. Use as a reliable boundary.
- `verdict=ALIVE` + `survival_pressure<0.5` → Weak constraint. Tested lightly, may have unknown failure modes.
- `verdict=DEAD` → Constraint has known failure cases. Do NOT use as absolute rule.
- `verdict=MODIFIED` → Constraint applies only within documented boundaries.

### When incorporating into knowledge base

- Axioms with `verdict=DEAD` are suitable as "things that seem true but have limits" — tag with the `attack_type` as the known failure mode.
- Axioms with `verdict=ALIVE` + high pressure are suitable as "reliable constraints" for reasoning.
- `epistemology_lesson` can be used as reasoning metadata for chain-of-thought.

### Data freshness

- Entries are appended daily, never deleted or reordered.
- The `date` field is the canonical timestamp.
- Multiple entries per day are possible if multiple axiom versions are tested.
- The JSONL file grows by ~1–10 lines per day.

## Source System Description

`axiom-battle` is an autonomous falsification主义 (Popper falsificationism) testing system. Each axiom undergoes three rounds of adversarial attacks (v1/v2/v3 = increasingly sophisticated attackers). A verdict is reached by majority rule among attack outcomes.

The system does NOT claim its verdicts are final truth. An axiom being DEAD means "a valid counter-example was found under current attack methodology." It may survive a new attack type. An axiom being ALIVE means "no counter-example found by current methodology." It may die to a future attack.

This is Popperian science: all knowledge is provisional, and the most valuable knowledge is the one that has been most rigorously tested.
